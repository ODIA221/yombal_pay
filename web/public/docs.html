Documentation YombalPay

YombalPay permet à un site ou à une boutique d'encaisser en Bitcoin (réseau Lightning) avec des prix en FCFA. Vous envoyez un montant en FCFA, nous créons la facture Lightning, votre client paie depuis n'importe quel pays, et nous vous prévenons dès que c'est payé.

Il y a deux façons d'utiliser YombalPay :

  • Sans code : depuis votre espace marchand, vous encaissez à la caisse, par un lien de paiement ou par votre page publique. Voir Encaisser sans site web.
  • Avec l'API : votre site web crée les paiements automatiquement. C'est le reste de cette page.

Adresse de votre passerelle : https://votre-passerelle. Tous les exemples de cette page l'utilisent déjà.

Démarrage rapide

Votre premier paiement en cinq minutes.

  1. Créez un compte sur la page d'inscription. Votre clé API secrète (sk_…) s'affiche une seule fois : copiez-la. Vous pourrez en créer d'autres dans Développeurs.
  2. Confirmez votre adresse e-mail avec le lien reçu. Tant qu'elle n'est pas confirmée, la création de paiement est refusée (email_unverified). Un compte créé avec Google est déjà confirmé.
  3. Créez un paiement depuis votre serveur, en remplaçant VOTRE_CLE : 
    curl https://votre-passerelle/v1/checkouts \
  -H "Authorization: Bearer VOTRE_CLE" \
  -H "Content-Type: application/json" \
  -d '{"amount": 5000, "currency": "XOF", "reference": "commande-1042"}'
    La réponse contient pay_url : c'est la page de paiement.
  4. Envoyez votre client sur pay_url. Il voit le montant en FCFA et en sats, le QR Lightning, et peut aussi payer en USDT.
  5. Soyez prévenu : ajoutez webhook_url à la requête (ou réglez une adresse par défaut dans Développeurs), et YombalPay l'appellera dès que le paiement est confirmé. Voir Webhooks.

Encaisser sans site web

Pour une boutique physique ou une vente sur WhatsApp, pas besoin de développeur :

  1. Ouvrez la caisse de votre espace marchand, tapez le montant en FCFA, puis Encaisser.
  2. Montrez le QR code à votre client. L'écran passe au vert dès que le paiement est confirmé.
  3. Pour vendre à distance, créez un lien de paiement à montant fixe à partager sur WhatsApp, ou envoyez votre page publique /@identifiant et votre adresse Lightning identifiant@domaine.

Authentification

Chaque requête porte votre clé secrète, dans l'un de ces en-têtes :

Authorization: Bearer sk_…        # recommandé
X-API-Key: sk_…

La clé publique pk_… (affichée dans Développeurs) peut seulement créer des paiements : elle sert au bouton navigateur. Elle ne lit pas vos paiements et ne déclenche jamais de retrait.

La clé secrète reste sur votre serveur. Ne la mettez jamais dans le code de votre site visible par les visiteurs, ni sur GitHub. Si elle a fuité, révoquez-la dans Développeurs : elle cesse aussitôt de fonctionner.

Référence API

Adresse de base : https://votre-passerelle/v1. Les corps de requête et de réponse sont en JSON.

POST/v1/checkoutssk_ ou pk_

Crée un paiement. Le montant en sats est calculé au cours du moment et reste garanti 15 minutes. Réponse 201, ou 200 si la référence existait déjà.

ChampTypeDescription
amount obligatoireentierMontant en FCFA, de 100 à 5 000 000.
currency facultatiftexteXOF (franc CFA), seule devise acceptée.
reference facultatiftexteVotre numéro de commande. Renvoyer la même référence redonne le même paiement : pas de doublon si votre site réessaie.
description facultatiftexteAffichée au client sur la page de paiement (140 caractères).
return_url facultatifURLOù renvoyer le client après le paiement (http ou https).
webhook_url facultatifURLOù envoyer checkout.paid pour ce paiement. Clé secrète uniquement ; en production, https vers une adresse publique.
customer_email facultatiftexteE-mail du client, pour vos rapprochements.
metadata facultatifobjetVos données libres, renvoyées telles quelles.

GET/v1/checkouts/:id

Renvoie un paiement. Avec votre clé secrète, la réponse ajoute les détails privés (commission, preuve de paiement). Un paiement d'un autre compte répond 404.

GET/v1/checkoutssk_

Renvoie vos paiements du plus récent au plus ancien dans data. Paramètres : status (pending, paid, expired), limit (100 par défaut, 500 au plus).

POST/v1/payment-linkssk_

Crée un lien de paiement à montant fixe (amount, description). Chaque ouverture du lien crée un nouveau paiement.

GET/v1/rates

Cours du moment : xof_per_btc, sats_per_1000_xof. Sans authentification.

POST/v1/checkouts/:id/simulate-payment

Mode démo seulement : marque le paiement comme payé, comme si le client avait payé. Voir Mode test.

Webhooks

Un webhook est un message que YombalPay envoie à votre serveur quand un paiement est confirmé. Votre site n'a pas besoin de demander le statut en boucle : c'est nous qui vous prévenons.

Nous envoyons un POST au webhook_url du paiement, sinon à l'adresse par défaut réglée dans Développeurs :

{
  "id": "evt_3c1e…",
  "type": "checkout.paid",
  "created_at": "2026-10-18T10:43:10Z",
  "data": { "id": "chk_6ASjVMv4pNh", "status": "paid", "reference": "commande-1042", "amount": 12500, … }
}

Vérifier que le message vient bien de YombalPay

Chaque message porte l'en-tête X-YombalPay-Signature: t=…,v1=…. v1 est le HMAC-SHA256 de t + "." + corps avec votre secret de webhooks (whsec_…, dans Développeurs). Refusez tout message dont la signature ne correspond pas, ou trop ancien.

// Node.js avec Express
import crypto from "node:crypto";

app.post("/hooks/yombalpay", express.raw({ type: "application/json" }), (req, res) => {
  const { t, v1 } = Object.fromEntries(req.get("x-yombalpay-signature").split(",").map((p) => p.split("=")));
  const attendu = crypto.createHmac("sha256", process.env.YOMBALPAY_WEBHOOK_SECRET)
    .update(`${t}.${req.body}`).digest("hex");
  if (attendu !== v1 || Date.now() / 1000 - Number(t) > 300) return res.status(400).end();

  const event = JSON.parse(req.body);
  if (event.type === "checkout.paid") {
    // marquer la commande event.data.reference comme payée
  }
  res.json({ received: true });
});

Répondez avec un code 2xx en moins de 10 secondes. Sinon, nous réessayons après 2 s, 5 s, 15 s, 30 s et 60 s. Chaque envoi est visible dans Développeurs, avec un bouton pour le renvoyer. Pour une sécurité maximale, relisez le paiement avec GET /v1/checkouts/:id avant de livrer.

Mode test

Deux façons de tester sans dépenser de vrais bitcoins :

  • Mode démo (passerelle sans clés Bitnob, ou DEMO_MODE=true) : les factures sont simulées. Sur la page de paiement, cliquez sur Simuler le paiement, ou appelez POST /v1/checkouts/:id/simulate-payment.
  • Bitnob sandbox : les factures sont de vraies factures du réseau de test (elles commencent par lntb). Payez-les depuis un portefeuille de test, ou avec ./run.sh pay chk_… sur la passerelle.

Le paiement passe à paid et votre webhook est envoyé, exactement comme en vrai.

SDK et bouton

SDK Node.js

import YombalPay from "yombalpay";

const yp = new YombalPay({ apiKey: process.env.YOMBALPAY_SECRET_KEY, baseUrl: "https://votre-passerelle" });
const paiement = await yp.createCheckout({ amount: 5000, reference: "commande-1042", returnUrl: "https://maboutique.sn/merci" });
res.redirect(paiement.pay_url);

// Dans votre route webhook (corps brut) :
const event = YombalPay.verifyWebhook(req.body, req.get("x-yombalpay-signature"), process.env.YOMBALPAY_WEBHOOK_SECRET);

Bouton « Payer en Bitcoin », sans code

<script src="https://votre-passerelle/sdk/yombalpay.js"
        data-key="pk_…" data-amount="5000" data-reference="CMD-42"></script>

Le bouton utilise votre clé publique pk_… : il peut être placé sur n'importe quelle page de votre site.

Exemples par langage

Votre site est écrit dans un langage de programmation. Choisissez le vôtre : c'est la même requête (« crée un paiement de 5 000 FCFA ») écrite de quatre façons. cURL se lance dans un terminal, pratique pour tester. Node.js (JavaScript), Python et PHP sont les langages les plus courants pour les sites web : WordPress, par exemple, est en PHP.

curl https://votre-passerelle/v1/checkouts \
  -H "Authorization: Bearer VOTRE_CLE" \
  -H "Content-Type: application/json" \
  -d '{"amount": 5000, "currency": "XOF", "reference": "commande-1042"}'
const res = await fetch("https://votre-passerelle/v1/checkouts", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.YOMBALPAY_SECRET_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ amount: 5000, currency: "XOF", reference: "commande-1042" }),
});
const paiement = await res.json();
// rediriger le client vers paiement.pay_url
import os, requests

paiement = requests.post(
    "https://votre-passerelle/v1/checkouts",
    headers={"Authorization": f"Bearer {os.environ['YOMBALPAY_SECRET_KEY']}"},
    json={"amount": 5000, "currency": "XOF", "reference": "commande-1042"},
).json()

# rediriger le client vers paiement["pay_url"]
$ch = curl_init('https://votre-passerelle/v1/checkouts');
curl_setopt_array($ch, [
  CURLOPT_HTTPHEADER     => ['Authorization: Bearer ' . getenv('YOMBALPAY_SECRET_KEY'), 'Content-Type: application/json'],
  CURLOPT_POSTFIELDS     => json_encode(['amount' => 5000, 'currency' => 'XOF', 'reference' => 'commande-1042']),
  CURLOPT_RETURNTRANSFER => true,
]);
$paiement = json_decode(curl_exec($ch), true);
header('Location: ' . $paiement['pay_url']);   // rediriger le client
